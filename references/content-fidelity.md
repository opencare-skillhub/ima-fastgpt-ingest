# 正文、要点与完整性核验

## 两类产物，保留同一来源

正文是证据底座，默认保留主要医学章节，不做摘要替换。要点可作为导读和检索辅助，适合提炼定义、操作顺序、观察项目、就医提醒及适用条件；是否生成或额外入库按用户需求决定。不要把“要点提取不错”理解为允许删掉其它正文。

```text
output/<任务>/
  parsed/         MinerU原始MD、图片、版面JSON与原页映射
  fastgpt/        保留医学主体、补齐来源后的入库MD
  keypoints/      可选要点及原页引文，不覆盖正文
  manifest.json   每份文档路径、hash、计数、版本与来源
  verification.json  当次线上采集的脱敏集合元数据和检索证据
```

使用稳定来源ID串联原件、解析段、正文和要点。正文与要点各自有hash和版本，若两类均上传，去重身份须区分`body`与`keypoints`，不能只截取来源ID导致要点覆盖正文。使用fgkb时核对其identity正则与同名闸门；JSON侧车不能假定FastGPT可直接解析，应明确转换为受支持的MD再按授权上传。

## 正文处理

- 清理封面、版权、序言、目录、广告与确认重复的页眉页脚；保存原文页范围和逐块删除原因。
- 患者生活/励志叙事可按用户要求去除；医学病历、检查、诊疗过程和病例分析保留，不能用“病例”“例如”匹配整页删除。
- 保留药名、剂量、单位、否定词、适用条件、表格、公式、图注、参考文献及未知类型中的医学负载。部分OCR `code`块实际是分期表。
- 旧版、作者观点、研究进展及跨癌种章节保留原文并标资料性质，不整本排除或包装成现行规范。
- 原始MD不覆盖；清洗后复查书名、版本、章节、原PDF物理页和简短风险提示。统计医学原文量与来源提示量，不能用提示撑大的总字数当作正文保留率。

对保留的解析块做逐字子串或有记录的格式归一化核验；用删除清单确认缩减发生在已说明的范围。原文中后段及表格、脚注、参考文献都要覆盖，不能只抽查第一页。

## 要点提取

每条要点记录：正文版本hash、原书/章节、物理页、可逐字核对的原句、简短要点、原文适用条件及需要核实之处。剂量、阈值、否定词与例外不得被概括掉；原文没有的信息不补写。生成的归纳须标识为归纳，与原句分开。

医学事实以原文为准。要点不扩大原文证据等级，不把个案结果写成普遍疗效，不将学术探索写成已获批方案。人工核对归纳是否被原句支持；存在引文不等于概括忠实。

可选JSON侧车格式：根字段`body_sha256`对应入库正文的SHA256，`items`为要点数组；每项含`key_point`、`source_quote`、`source_pages`。引文应直接从正文截取，物理页必须与原PDF核对。正文变化后重新提取或复核侧车，不继续沿用旧hash。

## 可复用离线核验

```bash
python3 scripts/verify_content_manifest.py \
  --manifest '<任务manifest.json>' \
  --output-root '<项目output目录>' \
  --remote-snapshot '<脱敏verification.json>'
```

`--remote-snapshot`可省略，此时只核本地。脚本仅使用Python标准库，不联网、不读取环境凭据、不输出正文、要点内容或私有ID。退出码：0通过，1存在不匹配，2输入格式错误。

manifest根字段`books`为非空数组；提供远端快照时还需匹配`dataset_id`。每份正文要求：

| 字段 | 用途 |
| --- | --- |
| `title` | 唯一文档标题，用于对齐快照；同名需先正规化身份，不能任意合并 |
| `file` | 相对output根的MD路径；解析后的路径不能逃出output，包含符号链接 |
| `sha256` | 正文文件的64位小写SHA256 |
| `bytes` | 本地正文文件字节数 |
| `uploaded_document_chars` | 正文文档Python字符数，含出处提示 |
| `keypoints_file` | 可选JSON侧车路径 |
| `medical_body_range` | 检查要点物理页范围时使用的起止页，不是自动删减指令 |

远端快照`files`数组按唯一`title`对齐，每项含`collection_id`、`remote_raw_text_length`、`remote_bytes`、`index_amount`、`error_count`。分别来自本次采集的集合ID、`rawTextLength`、`file.length`、`indexAmount`和`errorCount`。脚本不信任快照里的自报`passed`，会重新比较长度、字节数、索引非空和错误数为0；不能用旧快照宣称当前线上状态。

要点侧车只自动检查正文hash、引文存在和页码在范围内；**不证明页码与引文逐页对应、不证明医学准确或归纳蕴含关系**。正文hash也只防止与基线不一致，不能证明基线就是完整原书；还须结合原始块核验和删除清单。

## 线上验收与收尾

1. 锁定实际实例、知识库及当前正文目录，逐份采集原文长度与字节数，按服务端实际字段/字符计数比较。
2. 单独等待embedding进度，检查可用索引和错误，不能只看上传回执。
3. 使用中段及后段已知原文核对正确集合和事实。通用句可能召回其它相近段落：保留首次未命中记录，用章节上下文或相邻原句复核，仍要求正确来源和真实文本，不改变正文迎合检索。
4. 新版验证后才退役属于本次账本的旧样本/节选，核对ID、名称、父目录和类型；旧目录确认为空才删除。保留本地归档和回滚记录。
5. 再次同步要求不新增重复项；更新当前manifest、报告、要点hash与目录指向，防止用户继续打开小样本或旧节选。
